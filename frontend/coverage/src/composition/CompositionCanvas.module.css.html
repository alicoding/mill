   above blocks every descendant control FUNCTIONALLY (native <fieldset
   disabled> cascades to any input/select/textarea/button no matter how
   deep it's nested through other React components), but it does nothing
   VISUALLY -- investigated directly against the installed Primer build
   (node_modules/@primer/react/dist/internal/components/
   TextInputWrapper-*.css, Select's own Select.module.css.js): TextInput/
   Select/Textarea key their muted background/border off their OWN
   `disabled` REACT PROP (which stamps a `data-disabled` attribute on
   their internal wrapper span), never off the native `:disabled` CSS
   pseudo-class the fieldset cascade actually puts on the real
   <input>/<select> underneath. Threading an explicit `disabled` prop
   through NodeInspector's half-dozen nested editors (Integration
   BindingsEditor, ChildWorkflowBindingsEditor, MCPToolArgsEditor,

   covers every current AND future control uniformly. Same opacity +
